# Architecture

[spec.md](./spec.md) の仕様を、Zsh の ZLE（Zsh Line Editor）ラッパーと Rust 製 CLI バイナリの 2 層で実現する。Zsh 専用ツールとして設計し、他シェル向けの抽象層は設けない。

## 全体構成

```text
Zsh (ZLE wrapper)
  │ BUFFER / LBUFFER / CURSOR / tokens
  ▼
zrs (Rust CLI)
  ├── YAML config loader & validator
  ├── Abbreviation engine ──┐
  ├── Snippet engine      ──┴── Template / placeholder engine
  ├── History selector (no config load)
  └── Completion engine
        ├── External commands (source / preview)
        └── fzf
```

外部プロセスから親プロセスである Zsh の入力バッファを直接書き換えることはできない。そのため責務を次のように分ける。

- **ZLE ラッパー（Zsh スクリプト）**: キー入力の捕捉、`BUFFER` / `LBUFFER` / `RBUFFER` / `CURSOR` の読み書き、標準補完へのフォールバック呼び出し。
- **`zrs`（Rust CLI）**: YAML 設定の読み込みと検証、略語・スニペット・補完ルールの評価、共通テンプレートエンジンによるプレースホルダー展開とカーソル位置計算、外部コマンドおよび `fzf` の呼び出し。

設定スキーマ上は `abbreviations` と `snippets` を別の型として分離し、略語にしか意味を持たない照合条件（`keyword`、`global`、`context` 等）を型レベルで制約する。一方で、展開結果のプレースホルダー解析とカーソル位置計算は共通モジュールにまとめる。履歴選択は設定を参照せず、履歴レコードの NUL 区切りデコードと fzf 呼び出しのみを担当する。

## 実行モデル

キー操作のたびに `zrs` バイナリを起動して結果を返す同期ワンショットモデルを採用する。

- 常駐サーバー（Unix ドメインソケット IPC）や非同期ランタイム（Tokio 等）は持たない。単一ネイティブバイナリで完結させ、ランタイム依存と常駐プロセス管理を省くためである。
- Space 押下ごとにプロセス起動と YAML パースが走るため、入力応答性が実用基準を満たすかは実測を前提とする。このコストが許容範囲を超える場合は、設定キャッシュの導入または常駐 IPC 化への移行を検討する。

## 技術選定

| 領域 | 採用技術 | 理由・割り切り |
| --- | --- | --- |
| コア実装 | Rust | 単一ネイティブバイナリとして配布でき、起動オーバーヘッドを抑えやすい |
| CLI | `clap` | サブコマンドと引数解析の標準手段 |
| 設定デシリアライズ | `serde` + `serde-saphyr` | Pure Rust の YAML パーサーで型付き読み込みと未知フィールド拒否を行う |
| 正規表現 | `regex` | 略語展開・補完パターンの照合 |
| エラー処理 | `thiserror` | 構造化エラーの定義 |
| ファジー検索 UI | `fzf` | 外部コマンドへ委譲し、`nucleo` / `skim` による UI 内製を避ける |
| シェル統合 | Zsh ZLE | 入力バッファ操作の唯一の接点 |

## 拡張と設定の境界

動的設定のための組み込みスクリプトエンジン（Rhai / Lua / WASM 等）は採用しない。補完候補の生成（`source`）・プレビュー表示（`preview`）および略語のコマンド評価展開（`evaluate: true`）を任意の外部コマンドに委ねることで、YAML の宣言的記述だけで拡張性を確保する。

`evaluate: true` のコマンドおよび補完の `source` コマンドは、該当ルールが一致したときにのみ実行する（設定読み込み時の事前評価は行わない）。実行には `.zshrc` を読み込まない非対話 Zsh（`zsh -fc`）を用い、シェル構文をそのまま扱いつつ起動コストを抑える。補完の `preview` は `fzf --preview` へそのまま委譲し、`{}` のクォート展開は `fzf` 側に任せる。

## 設計上の技術的制約と方針

### シェル構文・コンテキスト解析

Rust 側で Zsh の字句・構文パーサーを全面的に再実装しない。Zsh 固有のパラメータ展開 `${(z)LBUFFER}` を使って ZLE 側でトークン分割した結果を受け取り、コマンド位置の判定に利用する。

ただし `${(z)LBUFFER}` は閉じられていない引用符やコマンド置換などの未完成構文を完全には扱えない。そのため Rust 側で `LBUFFER` に対する軽量な構文スキャンを行い、未閉じの引用符・展開および引用符・エスケープを含む末尾トークンを検出した場合は安全側（展開抑止）に倒す。

### CLI サブコマンドと ZLE 境界プロトコル

ZLE スクリプトはバイナリ内に `include_str!` で埋め込み、`zrs-zsh init`（および `--no-keybinds`）で出力して単一バイナリ配布を維持する。CLI サブコマンドは `init`、`validate`、および ZLE から呼び出す `expand`、`placeholder`、`snippet`、`complete` の 6 つとする。

CLI サブコマンドは `init`、`validate`、および ZLE から呼び出す `expand`、`placeholder`、`snippet`、`history`、`complete` の 7 つとする。`history` 以外の対話サブコマンドは設定を読むが、`history` は設定ファイルが存在しない・壊れている場合でも動くよう YAML を一切読まない。履歴候補は ZLE 側が Zsh の `$history` パラメータ（新着順）から NUL 区切りレコードとして標準入力へ渡す。

設定パス解決は環境変数 `XDG_CONFIG_HOME` と `HOME` を直接参照して行う。macOS で `~/Library/Application Support` を返す OS 既定ディレクトリ系クレート（`dirs` 等）は使用しない。

ZLE 側に `jq` 依存や `eval` を持ち込まないため、境界プロトコルを次のように統一する。

- **入力渡し**: `-` 始まりの入力文字列をオプションと誤認させないため、`--lbuffer=...` / `--rbuffer=...` の `=` 結合形式で渡す。`expand` 用の `${(z)LBUFFER}` トークン配列と `history` 用の `$history` レコード配列は NUL（`\0`）区切りで標準入力へ渡す。
- **補完クエリ**: ZLE は置換対象の末尾トークンを `--word=...` で渡し、そのクォートを外した検索語を `--query=...` で渡す。
- **終了コード**:
  - `0`: バッファ更新あり（標準出力に更新内容を返す）
  - `1`: エラー（標準エラー出力に詳細を出し、ZLE 側は `zle -M` で通知してバッファを維持する）
  - `2`: 該当なし / ルール不一致（通常入力継続または標準補完へのフォールバック）
  - `3`: ルール一致済みだがキャンセルまたは候補 0 件（フォールバックせずバッファを維持する）
- **標準出力（終了コード `0` 時）**: 全更新系サブコマンドで共通の NUL 終端 3 フィールド `<kind>\0<new_buffer>\0<cursor_chars>\0` を返す（`<kind>` は `placeholder` または `normal`、`<cursor_chars>` は文字単位のカーソル位置）。ZLE 側は単一の読み取りヘルパーで `BUFFER` と `CURSOR` を更新する。

### ZLE ウィジェット統合と境界処理

[spec.md](./spec.md) の共存・正確性要件を満たすため、ZLE 境界では次を扱う。

- **ウィジェット連携**: 初期化時に `Space` / `Enter` / `Tab` の既存バインド先を退避して保持し、未展開・フォールバック時に呼び出す。再初期化時に自前の `_zrs_*` ウィジェットを退避先として上書きしないようガードし、読み込み順序への依存を最小化する。
- **TTY 制御**: `snippet` / `complete` で `fzf` を対話起動する際、標準出力は ZLE への結果返却に専念させ、`fzf` の対話 UI は制御端末（`/dev/tty`）に接続する。
- **候補の受け渡し**: `fzf` とは NUL 区切りで候補を受け渡す。標準出力の形式と選択操作を固定するため、この起動では `FZF_DEFAULT_OPTS` と `FZF_DEFAULT_OPTS_FILE` を参照しない。履歴選択は `--tiebreak=index` で履歴の新着順を保ち、選択結果をクォートやプレースホルダー展開なしでバッファ全体へ復元する。
- **文字単位のカーソル変換**: Rust 内部の文字列は UTF-8 のバイトオフセットだが、ZLE の `CURSOR` は文字単位である。マルチバイト文字を含む行でカーソル位置がずれないよう、境界で文字数へ変換する。
- **クォーティング**: 補完で選択した候補をコマンドラインへ戻す際、空白や記号を含む値が壊れないよう Zsh 向けのシェルエスケープを施す。

### エラー処理

YAML の構文誤り、スキーマ違反、外部コマンドの失敗を黙示的な既定値で隠さない。エラーを明示的に返して ZLE 側へ通知し、意図しないバッファ破壊を防ぐ。
