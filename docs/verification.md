# Verification

[spec.md](./spec.md) の契約と [architecture.md](./architecture.md) の境界処理が満たされているかを判定するための検証構成と合格基準を定める。実行コマンドは [development.md](./development.md) を参照する。

## 検証の層と観測対象

| 層 | 対象 | 合格基準 |
| --- | --- | --- |
| 静的解析・構文チェック | Rust コード、`shell/zrs.zsh` | `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`zsh -n shell/zrs.zsh` がすべて警告・エラー 0 で終了すること |
| Rust 単体テスト | 設定検証、構文ガード、コマンド位置判定、プレースホルダー、クォーティング、履歴、プロトコル | 下表の観点すべてが `cargo test --lib` で通ること |
| CLI 結合テスト | 実バイナリのサブコマンド・終了コード・標準出力/標準エラー | 一時設定ファイルおよびモック `fzf` / 外部コマンドを用いた `cargo test --test '*'` が通ること |
| Zsh ZLE E2E テスト | ZLE ウィジェット、`BUFFER` / `CURSOR`、キーバインド、フォールバック | 擬似端末（`zsh/zpty`）上で実際のキー入力を送り、バッファ内容・カーソル位置・フォールバック動作が期待通りであること |
| Nix サンドボックス検証 | 配布パッケージと全自動チェック | `nix flake check`（`package` / `clippy` / `fmt` / `zsh-syntax` / `zsh-e2e`）が通ること |

## 機能・境界ごとの検証観点

### 設定読み込みと検証

- `abbreviations` / `snippets` / `completions` の省略時に空リストとして読み込まれること。
- 構文誤り、必須項目欠落、未知フィールド、不正な正規表現、`global: true` と `context` の同時指定がエラーになること。
- 設定ファイル未存在時、`zrs-zsh validate` はエラー（終了コード `1`）、対話コマンドは空設定扱い（終了コード `2`）になること。
- `$XDG_CONFIG_HOME` の設定有無にかかわらず仕様通りのパスが解決されること。

### 略語展開と文脈ガード

- 通常展開がコマンド位置（行頭、制御演算子・予約語・環境変数代入・ラッパーコマンド直後）でのみ発火し、引数位置では発火しないこと。
- `global: true` と `context`（`lbuffer` / `rbuffer` / `buffer` の AND 評価）が仕様通りに照合され、複数一致時は記述順の先頭が選ばれること。
- 末尾空白、引用符・エスケープ付き末尾語、未閉じの引用符（`'`, `"`, `$'...'`）および未閉じの展開（`$(`, `` ` ``, `${`）では、通常 / `global` / `context` いずれも展開されないこと。
- `evaluate: true` で標準出力の末尾改行が除去されて展開され、非ゼロ終了時はエラー通知かつバッファ無変更であること。

### プレースホルダーとマルチバイト文字

- 展開直後に最初の `{{...}}`（名前付きおよび `{{}}`）が削除されてカーソルがその位置へ移動し、2 個目以降は残ること。
- Space 展開時にプレースホルダーありなら末尾空白が付かず、Enter 展開時にプレースホルダーありなら実行されず入力待ちになること。
- プレースホルダー移動がカーソル以降を検索し、末尾になければ行頭からラップアラウンドすること。
- 日本語などのマルチバイト文字を含む行で、Rust が出力する文字単位カーソル位置と ZLE の `CURSOR` が一致すること。

### スニペットとカスタムファジー補完

- スニペット選択後に現在カーソル位置へ本文が挿入され、プレースホルダーがあれば移動すること。
- 補完ルール一致時に末尾非空白語が初期クエリとして渡され、確定時にその末尾語が置換されること。末尾空白時はそのまま挿入されること。
- `multi: true` で複数候補が個別に Zsh クォートされてスペース連結されること（空白、引用符、メタ文字、改行、マルチバイト文字を含む値で壊れないこと）。
- ルール不一致は終了コード `2` で既存 `Tab` ウィジェットへフォールバックし、ルール一致後の候補 0 件またはキャンセルは終了コード `3` でフォールバックせずバッファを維持すること。`source` の非ゼロ終了はエラー（終了コード `1`）でバッファを維持すること。

### 履歴選択

- `^R` で `zrs-zsh history` が Zsh `$history` のレコードを新着順に fzf へ渡し、選択したレコードで `BUFFER` 全体が置き換わり、文字単位の `CURSOR` が末尾へ移動すること（複数行・マルチバイト文字を含むレコードでも壊れないこと）。
- `--lbuffer` が fzf の初期検索クエリとして渡されること。キャンセル時は終了コード `3` で `BUFFER` / `CURSOR` が保持され、`zle reset-prompt` が実行されること。
- 空白のみの履歴レコードが候補から除外され、重複は除去されず入力順に渡されること。UTF-8 として不正なレコードがあってもコマンドは失敗せず、正当なレコードが選択できること。
- 履歴が空のときは fzf を起動せずバッファを保持すること。設定ファイルが存在しない・不正でも `zrs-zsh history` が正常に動作すること。

### 共存・応答性

- `zrs-zsh init` の再実行で既存の `Space` / `Enter` / `Tab` / `^R` 退避先が自前ウィジェットで上書きされないこと。`zrs-zsh init --no-keybinds` でキーバインドが張られないこと。
- `zsh-autosuggestions`、`zsh-syntax-highlighting`、`fzf-tab`、`zsh-vi-mode`、`Atuin` との併用時に標準補完フォールバックや TTY 表示が破綻しないこと（対話確認）。
- 入力応答性: リリースビルドの `zrs-zsh expand` を、現実的なルール数（例: 略語 50〜100 件・スニペット 30 件・補完 20 件）の設定に対して `hyperfine` で実測し、日常の Space 入力を妨げる体感遅延がないことを確認する。
